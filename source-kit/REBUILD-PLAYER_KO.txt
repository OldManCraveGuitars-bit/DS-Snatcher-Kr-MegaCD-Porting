플레이어 소스 복원과 NDS 재빌드 — 개발자용 선택 절차

일반 플레이용 NDS는 Patch-development.cmd로 만듭니다. 아래 절차에는 별도의
ARM 개발 도구가 필요하며, 사용자가 가진 원본과 이미 생성한 NDS를 이용합니다.

1. 패처의 requirements.txt 의존성을 설치한 Python 3.12 이상, 64비트를 사용합니다.
   패처 폴더에서 다음 명령을 실행합니다.

py -3 -I -X utf8 -B patcher/prepare_player_rebuild.py --source "D:/Original/Snatcher (USA).cue" --nds "D:/Snatcher-Output/snatcher_ds.nds" --output "D:/Snatcher-Source"

   원본 CUE가 참조하는 모든 BIN 트랙을 함께 두어야 합니다.
   소스 출력 폴더는 기존에 없는 폴더로 지정하며, 패처·원본 CUE·생성 NDS가
   들어 있는 폴더의 하위 경로는 사용하지 않습니다. 도구가 NDS의 1,230개
   리소스를 검사하고 원본 의존 헤더·글꼴을 새 소스 폴더에 복원합니다.
   동봉 player/ 폴더를 직접 수정하거나 빈 원본 표를 임의로 채우지 않습니다.

2. BlocksDS/Wonderful의 ARM 개발 환경을 준비합니다.
   검증에 사용한 환경의 정확한 버전과 파일 해시는 BUILD-TOOLCHAIN.json에 있습니다.
   - blocksds-toolchain: 1.24.0-1 (도구의 버전 표시는 v1.24.0-dirty)
   - ARM GCC: 1~16.2.0.r229124.be93d9d35bf-1
   - ARM binutils: 2.47-2
   - libnds 원본 커밋: 4674cdfed005eb9a3699f4896e5c587ebc8b6a09
   - wf-fatfs 원본 커밋: 2b5c26e2a1eb4cdbbcb57070d49a6ebf7b60c7f9

   BlocksDS 소스: https://codeberg.org/blocksds/sdk
   libnds 소스: https://github.com/blocksds/libnds
   wf-fatfs 소스: https://github.com/blocksds/wf-fatfs
   SDK·컴파일러는 이 패처 ZIP에 포함되지 않습니다. 설치한 Wonderful 셸에서
   환경을 활성화합니다. MSYS2에 /opt/wonderful로 설치한 경우의 예:

source /opt/wonderful/bin/wf-env

   이 환경의 BLOCKSDS 경로와 ARM 컴파일러 실행 경로가 설정되어 있어야 합니다.
   저장장치 코드는 특정 SDK의 FatFs 구조를 사용합니다. Makefile은 libnds9.a의
   SHA-256을 검사하며, 다른 SDK라면 중단합니다. 검사를 삭제하거나 끄지 말고
   동봉 BUILD-TOOLCHAIN.json 및 player/include/storage_compat/sdk.json에 맞는
   SDK를 사용합니다. 다른 SDK의 재검토는 이 재빌드 안내의 범위에 포함되지 않습니다.

3. 새로 복원한 소스 폴더에서 ARM7, ARM9 순서로 빌드하고 실행 파일 고지를 붙입니다.
   MSYS2 셸에서 D:/Snatcher-Source는 /d/Snatcher-Source로 표시됩니다.

cd /d/Snatcher-Source
make -f Makefile.arm7 -j2
make -j2
python -B tools/binary_notices.py --kind nds --notices BINARY-NOTICES.txt snatcher_nds_resources_r22.nds

   Python 실행 이름이 python3이 아니면 make 명령에 PYTHON=python을 추가합니다.
   경로에 공백이 있는 Windows Python을 사용할 경우에는 SNATCHER_PYTHON 환경
   변수에 슬래시 표기의 절대 실행 파일 경로를 지정할 수 있습니다.
   소스 복원 단계에서 생성한 REBUILD-NOTICES_KO.txt에도 고지문 명령이 있습니다.
   이 파일은 ZIP 안이 아니라 새로 복원한 소스 출력 폴더에 생성됩니다.

4. 결과는 새 소스 폴더의 snatcher_nds_resources_r22.nds입니다.
   소스 재빌드와 일반 패처 출력은 NDS 파일 배치와 고지문으로 전체 해시가
   달라질 수 있습니다. 검증한 도구 환경에서 실행 코드와 1,230개 리소스를
   대조했습니다. 게임 내 저장 폴더를 백업한 뒤 결과를 시험합니다.

PC 변환 DLL을 소스에서 재빌드하려면 REBUILD-CONVERTERS_KO.txt를 참고합니다.
이 안내는 내부 소스 패키지에 대한 것입니다. 공개된 1회성 v0.1Demo 패처는
업데이트하지 않습니다. 전체 실기 검수와 모든 선택 분기를 보장하지 않습니다.

# v0.811 검증 범위

**전체 테스트용입니다. 실행 호환성 수정이며 모든 구간·모든 실기의 완전 검증은 아닙니다.**

- 새 Windows EXE에 원본 CUE/BIN과 BIOS를 넣어 리소스 **1,230개**와 NDS를 끝까지 생성했습니다. 입력 원본은 변경되지 않았습니다.
- Python 설치 경로 없이 실행, 한글·공백 경로, 잘못된 BIOS/BIN 누락/기존 출력 거부, 취소와 재시작, 진행 표시를 검사했습니다. GUI 콜백과 내장 Tk 창 생성 검사이며 수동 데스크톱 클릭 검사는 아닙니다.
- 새 EXE가 만든 NDS를 기존 v0.81 결과와 전체 바이트 비교했습니다. FAT 뒤의 `NitroFS!` 표식 **8바이트만 다르고**, 실행 코드·그림·대사·사운드 리소스는 같습니다.
- 파일 개수 1·63·64·65·1,230개로 조립 경계를 검사했습니다. FAT가 512바이트 경계에 맞을 때도 표식이 다음 데이터를 덮어쓰지 않습니다.

## 새 패처 출력의 실제 실행 검사

Windows의 아래 libretro 코어에서 새 프로필, 일반 DS 모드 **4MiB RAM**, 보통 터치 입력으로 실행했습니다. RAM 주입·세이브스테이트·오프닝 건너뛰기를 사용하지 않았습니다.

| 코어 | 검사 결과 | 디스플레이 프레임 |
| --- | --- | ---: |
| melonDS 0.9.3 66b5d26 | 시작 로고 → 타이틀 → 오프닝 1·2 → [접수처 도착](compatibility-v0.811/melonds-reception.png) | 28,603 |
| DeSmuME git 95b4d79 | 시작 로고 → 타이틀 → 오프닝 1·2 → [접수처 도착](compatibility-v0.811/desmume-reception.png) | 28,630 |

이는 **구형 RetroArch 코어의 실행 검사**입니다. melonDS 독립 실행판, Android APK, R4 실기에서 이번 출력의 실행·저장을 확인한 검사는 아닙니다.

## 저장 제한

구형 melonDS 0.9.3 코어에서는 게임 내 저장과 프로세스 재시작 후 불러오기를 실제로 조작했지만, 둘 다 **“SD 카드를 읽을 수 없습니다”**로 실패했습니다. 홈브루 SD가 제공되지 않기 때문이며 DSi SD 옵션과는 별개입니다.

이 저장 검사는 새 출력과 SHA-256이 같은 표식 수정 시험 파일에서 수행했습니다. v0.811의 실행 수정으로 코어 자체의 저장장치 미지원까지 해결되는 것은 아닙니다. melonDS DS는 다른 코어이며 홈브루 SD를 지원합니다.

## 이전 버전의 전체 경로 검사

v0.81에서는 같은 NDS·새 프로필·보통 입력·게임 내부 저장으로 **34개 구간 / 1,006,240 디스플레이 프레임**의 ACT 1~3 주요 경로·엔딩·재시작 후 클리어 기록/ACT 선택·5개 저장 슬롯을 확인했습니다. 이 기록은 [이전 검증 JSON](verification-v0.81.json)에 보존합니다.

v0.811에서 전체 경로를 다시 완주한 것은 아닙니다. 모든 선택 분기와 실기 성능은 여전히 미검증이며, 특정 장면의 사운드 끊김이 남아 있습니다.
